description: Declarative attributes for connecting Clap parsers to validated input, controllers, and command trees.

Clifacet provides a declarative, controller-centric authoring model built on pure Rust macros (decision-24). Rather than defining standalone command structs with manual bridge conversions, applications declare an application controller struct with `#[clifacet::app]` and implement command methods directly inside an `impl` block with `#[clifacet::commands]`.

Under the hood, the companion derive connects Clap argument parsing, typed input validation, prompt questionnaires, subcommand routing, and context propagation without boilerplate.

## The Canonical Controller Architecture

In Clifacet, the application controller struct holds global flags, configuration options, and shared context. Methods on its `#[clifacet::commands]` `impl` block become runnable CLI commands:

```rust
use clifacet::Failure;

/// An application controller declares its global surface and commands.
#[clifacet::app(name = "greet-app", about = "Say hello", commands)]
struct GreetApp {}

#[clifacet::commands]
impl GreetApp {
    /// Greet a user with customized repetitions.
    pub fn hello(
        &self,
        #[clifacet(long, short = 'n', help = "Who to greet", default_value = "world")]
        name: String,
        #[clifacet(long, help = "How many times to greet", default_value_t = 1)]
        repeat: u8,
    ) -> Result<String, Failure> {
        if repeat == 0 {
            return Err(Failure::validation("--repeat must be at least 1"));
        }
        Ok(format!("hello, {name} x{repeat}"))
    }
}
```

Key guarantees of the declarative controller model:

- **Single source of truth**: Method signatures define the command's typed inputs, documentation, argument grammar, and validation rules in one place.
- **Zero-cost context access**: Commands receive `&self`, providing direct access to global flags and shared application context without repetitive parameter drilling.
- **Pure command outcomes**: Methods return structured outcomes (`Result<T, Failure>`), separating core command logic from terminal rendering.
- **Automatic help generation**: Doc comments on the method are parsed into `about` (first line) and `long_about` (full description).

## Parameter and Field Attributes

`#[clifacet(..)]` on method parameters and controller fields configures CLI grammar, interactive questionnaire behavior, and input normalization in one place:

```rust
use clifacet::Failure;

#[clifacet::app(name = "task-app", about = "Manage tasks", commands)]
struct TaskApp {}

#[clifacet::commands]
impl TaskApp {
    /// Create a new task with interactive prompts and normalization.
    pub fn create(
        &self,
        #[clifacet(
            long,
            short = 't',
            value_name = "TITLE",
            help = "Task title",
            ask = "What is the task title?",
            trim,
            non_empty
        )]
        title: String,
        #[clifacet(
            long,
            value_name = "PRIORITY",
            help = "Task priority level (1 to 5)",
            range = 1..=5,
            default_value_t = 1
        )]
        priority: u8,
    ) -> Result<String, Failure> {
        Ok(format!("created task '{title}' with priority {priority}"))
    }
}
```

| Classification | Keys | Destination |
| --- | --- | --- |
| Grammar (with value) | `alias`, `conflicts_with`, `default_value`, `default_value_t`, `group`, `help`, `hide`, `id`, `num_args`, `required`, `requires`, `value_name` | Forwarded directly to Clap argument grammar |
| Grammar (flags) | `long`, `short`, `action = ArgAction::...` | Clap flag representation |
| Interactive Question | `ask = "prompt"`, `confirm = "prompt"`, `secret = "prompt"` | Conversational questionnaire or full-screen TUI form field |
| Normalization | `trim`, `non_empty`, `fill = fallback`, `range = min..=max` | Generated input validation and normalization bridge |

## Shared Context and Automatic Wiring

Stateful CLI applications frequently share services, connection pools, or API handles across commands. Clifacet automatically wires shared context onto the controller struct via `#[clifacet(context)]`.

Context initialization is strictly lazy: running `--help`, `--version`, or encountering argument syntax errors **never** invokes context creation.

```rust ignore
use clifacet::{Failure, FromCli};

struct DatabaseClient {
    endpoint: String,
}

struct AppContext {
    db: DatabaseClient,
}

impl FromCli for AppContext {
    type Cli = ServiceApp;

    fn from_cli(cli: &ServiceApp) -> Result<Self, Failure> {
        Ok(Self {
            db: DatabaseClient {
                endpoint: cli.db_url.clone(),
            },
        })
    }
}

#[clifacet::app(name = "service-app", about = "Service manager", commands)]
struct ServiceApp {
    #[clifacet(long, default_value = "postgres://localhost/app")]
    db_url: String,

    #[clifacet(context)]
    cx: AppContext,
}

#[clifacet::commands]
impl ServiceApp {
    /// Inspect database connection status.
    pub fn status(&self) -> Result<String, Failure> {
        Ok(format!("connected to {}", self.cx.db.endpoint))
    }
}
```

When an application context implements `FromCli`, Clifacet synthesizes `init_context` automatically. Custom factory functions are also supported using `#[clifacet(context = build_context)]` or `#[clifacet(context = Self::build_context)]`.

## Controller Lifecycle Hooks

Controllers can intercept command execution lifecycle by defining hook methods directly in the `#[clifacet::commands]` `impl` block:

- **`before_run`**: Runs immediately before command execution starts. Ideal for acquiring lockfiles, checking authorization, or initializing spans.
- **`after_success`**: Runs after a command successfully finishes. Ideal for emitting audit events or persisting caches.
- **`after_failure`**: Runs if a command returns an error or aborts. `cx` is an `Option`: if context initialization itself failed, `cx` is `None`. Ideal for rolling back scratch files, releasing locks, or logging troubleshooting guidance.

```rust ignore
use clifacet::Failure;

#[clifacet::app(name = "deployer", commands)]
struct DeployApp {
    #[clifacet(long)]
    environment: String,

    #[clifacet(context)]
    cx: DeployContext,
}

#[clifacet::commands]
impl DeployApp {
    /// Deploy service artifacts to target environment.
    pub fn deploy(&self, service: String) -> Result<String, Failure> {
        self.cx.push_artifacts(&service)?;
        Ok(format!("deployed {service} to {}", self.environment))
    }

    /// Pre-execution hook.
    fn before_run(&self, _cmd: &str, cx: &DeployContext) -> Result<(), Failure> {
        cx.acquire_deploy_lock()?;
        Ok(())
    }

    /// Success hook.
    fn after_success(&self, _cmd: &str, cx: &DeployContext) -> Result<(), Failure> {
        cx.release_deploy_lock();
        Ok(())
    }

    /// Failure remediation hook.
    fn after_failure(&self, _cmd: &str, _err: &Failure, cx: Option<&DeployContext>) {
        if let Some(cx) = cx {
            cx.rollback();
            cx.release_deploy_lock();
        }
    }
}
```

## Nested Command Groups

For applications with multi-level command hierarchies (such as `mycli user add` and `mycli user list`), subcommand groups are authored as nested controllers using `#[clifacet::group(commands)]` and `#[clifacet::commands(group)]`.

Mounting a group on the parent controller is declared by passing the group controller as a parameter annotated with `#[clifacet(subcommand)]`:

```rust ignore
use clifacet::Failure;

#[clifacet::group(commands)]
pub struct UserGroup {}

#[clifacet::commands(group)]
impl UserGroup {
    /// Add a new user account.
    pub fn add(&self, username: String) -> Result<String, Failure> {
        Ok(format!("user '{username}' created"))
    }

    /// List all existing user accounts.
    pub fn list(&self) -> Result<String, Failure> {
        Ok("alice, bob".to_string())
    }
}

#[clifacet::app(name = "mycli", about = "Fleet CLI", commands)]
pub struct MyCli {
    #[clifacet(long, short = 'v')]
    pub verbose: bool,
}

#[clifacet::commands]
impl MyCli {
    /// Display system health.
    pub fn health(&self) -> Result<String, Failure> {
        Ok("all systems operational".to_string())
    }

    /// Manage user accounts.
    pub fn user(&self, #[clifacet(subcommand)] group: UserGroup) -> Result<String, Failure> {
        group.execute()
    }
}
```

If the child group declares context fields annotated with `#[clifacet(context)]` or `#[clifacet(extract)]`, Clifacet automatically forwards the initialized context from the parent controller down into the group.

## Dry-Run Plans and Action Logging

Declarative controllers support previewing side effects in dry-run mode and logging actions across streams without interfering with stdout.

### Returning Plans from Controller Commands

Controller methods can return `Result<Plan<'_, T>, Failure>`. Clifacet automatically detects whether `--dry-run` was supplied:

- In **`--dry-run` mode**: The plan closure is never run. Clifacet formats and prints the declared steps (`plan.describe()`). When `--json` is also supplied, it formats the steps into structured JSON (`{"dry_run": true, "steps": [...]}`).
- In **real execution**: Clifacet executes the plan's closure and formats the returned payload.

```rust ignore
use clifacet::command::Plan;
use clifacet::{Failure, Globals};

#[clifacet::app(name = "tasks", commands)]
struct TaskApp {
    #[command(flatten)]
    #[clifacet(skip)]
    globals: Globals,
}

#[clifacet::commands]
impl TaskApp {
    /// Archive a task by identifier.
    pub fn archive(&self, task: String) -> Result<Plan<'_, String>, Failure> {
        let step = format!("archive task {task}");
        Ok(Plan::new(move || {
            // Real mutation only runs when --dry-run is absent
            Ok(format!("task {task} archived"))
        })
        .step(step))
    }
}
```

### ActionLog Context Helper

For commands that perform incremental steps, use `ActionLog` as an application context field (`#[clifacet(context)]`). Clifacet automatically initializes it with the application's dry-run setting via `FromCli`:

- **`ctx.log(message)`**: Emits messages to `stderr`. In dry-run mode, lines are prefixed with `[DRY-RUN]`.
- **`ctx.action(desc, closure)`**: Emits `desc` to `stderr`, executing the mutation only when `--dry-run` is not active. In dry-run mode, it returns `Ok(None)`.
- **Stream separation**: Diagnostic logging remains on `stderr` so `stdout` remains dedicated to structured data and clean command outcomes.

```rust ignore
use clifacet::{ActionLog, Failure, Globals};

#[clifacet::app(name = "deployer", commands)]
struct DeployApp {
    #[command(flatten)]
    #[clifacet(skip)]
    globals: Globals,

    #[clifacet(context)]
    ctx: ActionLog,
}

#[clifacet::commands]
impl DeployApp {
    /// Deploy service to target environment.
    pub fn deploy(&self, target: String) -> Result<String, Failure> {
        self.ctx.log(format!("preparing deployment to {target}"));
        self.ctx.action(format!("upload artifacts to {target}"), || {
            // Real network operation
            Ok(())
        })?;
        Ok(format!("successfully deployed to {target}"))
    }
}
```
