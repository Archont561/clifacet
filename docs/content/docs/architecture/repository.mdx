This page explains the structure of the Clifacet repository: why there are multiple crates, Pixi environment manifests, documentation workspaces, and Python tooling.

<Callout type="info">
The library does not know the repository exists: no crate reads local files at runtime. Examples are external consumers, and documentation code blocks are compiled as integration tests.
</Callout>

## Language and Tooling Ecosystem

| Component | Technology | Responsibility |
| --- | --- | --- |
| `crates/clifacet` | Rust | Command core, interaction policy, Inquire dialogs, and Ratatui TUI |
| `crates/clifacet-macros` | Rust (proc-macro) | `#[clifacet::command]`, `#[clifacet(..)]`, and `Facet` derive |
| `examples/` | Rust | End-to-end consumer crates ensuring public API stability |
| `docs/` | Next.js / Fumadocs / Bun | Documentation site with MDX and static export |
| `tools/` | Python / Tasknest | Repository linters, snippet extractors, and CI automation |
| `pixi.toml` | Pixi / Conda | Hermetic reproducible environment across Linux, macOS, and Windows |

## Generation Invariants

Several files are rendered from authoritative sources and committed to Git to make drift visible in pull requests:

| Committed Output | Authoritative Source | Generation Task |
| --- | --- | --- |
| `README.md` | `.readme/README.template.md` | `pixi run readme` |
| `CHANGELOG.md` | Conventional commits | `pixi run changelog` |
| `.vale.ini` | `vale.toml` | `pixi run prose-sync` |
| `examples/simple/tests/documented_snippets.rs` | MDX code blocks | `pixi run docs-snippets` |
