## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The generated tui form picks each field's kind from the clap grammar instead of offering a text box for everything: a choice for an argument with possible values, a toggle for a boolean flag, and a refusal for a list. A field declared secret is masked without the application having to remember it. Decision-18 consequence ("the tui form gains a choice field rather than a text field with a parser that rejects"); also fixes two shipped defects found while proposing it.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## Decision

Decision-18 consequence, accepted design: a generated form field is what its clap grammar says it is. `SetTrue`/`SetFalse` → toggle; non-hidden possible values → choice; `Set` with one value → text; anything else (`Append`, `Count`, more than one value, help/version actions) → refused. The value stays the string the field submits whatever the kind, so drawing, submission and a custom widget read one thing.

- `FormState::of::<C: Facet>()` = `generated(command, form_fields())` plus `mark_secret` for every `secret_fields()` entry; `Facet::secret_fields()` is a provided method (default empty), generated by the derive.
- Toggle: Space flips; value `"true"`/`"false"`; submits the bare flag only when the value equals what the flag sets (SetTrue on, SetFalse off). A fresh derive command has no flag default yet (clap fills it at build), so the form uses `!sets`.
- Choice: Space cycles; an optional choice passes through none (empty, submits nothing), a required one wraps to the first option; a letter jumps to the next option after the current one, wrapping, matching the first character case-insensitively; Backspace clears an optional choice and does nothing to a required one.
- `FieldState::toggle()` and `with_choices()` for hand-built forms; `choices()`, `is_toggle()`, `is_on()` for custom fields. `Field` draws `‹name›`/`‹(none)›` and `[x]`/`[ ]`; a non-empty secret still draws REDACTED first.
- The derive refuses `form` on `Vec<_>`/`Option<Vec<_>>` at the `form` key (read from the written type, like clap's derive; an alias hides it from both).
- Side change in 55a118d9: the `ask`-on-`secret` compile error points at `Session::ask_secret`.

## Narrowings

- No arrow keys: `Key` is unchanged (non-breaking), so a choice moves with Space and letters only; Up/Down would need new `Key` variants.
- No list field: lists are refused rather than edited; collect them with `Session::collect_values`.
- Possible values come only from the grammar: a custom `value_parser = fn` exposes none, so such a field stays text — that is why the example's `Level` moved to `clap::ValueEnum` (its refusal wording is now clap's, listing the values).
