## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Deferred** (decision-15, accepted in part on 2026-11-06): do not start until CLI-32 has moved `examples/backlog-lite` to the declarative tree and recorded what a `clifacet::commands!` macro would still save; if the saving is the `pub mod` lines and one enum, propose closing this card instead. If built: a command lives in its own module with a readable registration line, the registry is explicit, and `Request` stays hand-written (decision-14). Distributed registration, a proc-macro directory scan and a `clifacet-build` crate are refused. "A file per leaf" is a recommended convention in the guide, not a required layout. This card also carries CLI-34's macro-layering criteria (decision-16, narrowed), because it would ship the first exported `macro_rules!`.

## Implementation Notes

Gate (AC#1), measured 2026-11-03 on `examples/backlog-lite/src/commands/mod.rs` (125 lines) at `a80e3498`:

| What the file holds | Lines | Under `commands!` |
| --- | --- | --- |
| `mod` lines, one per leaf | 8 | generated |
| `pub(crate) use <leaf>::forward as forward_<leaf>;` | 7 | stays: `invocation_of` matches them by name |
| `pub use <leaf>::{Leaf, Payload};` | 8 | generated (re-export) |
| `enum Verb` (one variant per leaf) | 16 | generated |
| `enum Action` (one variant per validated input) | 16 | generated |
| `struct Request` | 5 | stays (the application's; decision-14) |
| generated `TryFrom<Verb> for Action`, `Collect`, dispatch | 0 | already generated by the attribute |

So about 55 of the 125 lines — 8 + 7 + 8 + 16 + 16 — fold into one call, of which 7 (`forward_*`) stay. Adding a leaf today touches five places (`mod`, `pub use`, `Verb`, `Action`, the `invocation_of` arm); under `commands!` it is the registration line plus the `invocation_of` arm, which the compiler demands because the generated `Request` gains a variant.

Go-ahead: 2026-11-03, the maintainer chose **build it now and migrate backlog-lite now** (CLI-48 rewrites the application afterwards, which is accepted: the registration is written twice rather than once, and CLI-48 measures the second one), **a generated `Cli` root with a hook for the application's own globals**, and **flat lists only** — a group is a separate `mod.rs` with its own `commands!`, until CLI-50's discovery adds nesting.

Interpretation, recorded rather than silently reworded:

- AC#3 says "`Request` is written by the application, not generated" (decision-14). Decision-19 item 3, accepted later, says "under `commands!` the `Request` is generated from the leaves' inputs; the `#[clifacet::subcommands]` attribute keeps the hand-written `Request` of decision-14". Both are honoured by keeping them apart: `commands!` generates one for its own tree, and every hand-written `#[clifacet::subcommands]` tree in the repository (including backlog-lite's, until it moves) is unchanged. The rest of AC#3 — nothing discovered globally, nothing registered by initialising a static — holds literally.
- AC#6's "tests unchanged" is read as "no test changes meaning". `commands!` names the items it generates (`Cli`, `Commands`, `Request`), so a leaf that backlog-lite calls `Verb` or `Action` today has to be renamed wherever the test names it. That rename is recorded in the notes when it happens.
