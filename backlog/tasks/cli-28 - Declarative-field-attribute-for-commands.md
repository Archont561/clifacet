## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
One `#[clifacet(...)]` per field, carrying grammar, interaction and normalization together, so an argument is declared once instead of four times (flag, input field, prompt question, form field list). Design and rationale: decision-13.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 `#[clifacet::command]` forwards grammar keys into an `#[arg(...)]` on the same field, in the spelling clap's derive accepts (`required = true`; `range` translated to clap's ranged parser), and a raw `#[arg(...)]` still passes through untouched.
- [x] #2 The interaction keys (`ask`, `confirm`) and normalization keys (`fill`, `trim`, `non_empty`, `secret`) are parsed and consumed by the generated `prompt::Collect` and the generated bridge; an answer to `ask` is parsed by the argument's own clap parser.
- [x] #3 The derive generates `TryFrom<Cli> for` the declared input from the field declarations: copy by name when no rule applies, `fill`/`trim`/`non_empty`/`secret` in that fixed order when one is declared.
- [x] #4 An unknown key, a `confirm` on a non-boolean, an `ask` on a non-`Option` or positional field, an `ask` on a `secret`, a rule on a type it cannot apply to, and a normalization rule beside a declared `bridge` each fail to compile at the key, with a trybuild case and a documented key table.
- [ ] #5 The TUI form's field list is generated from the same declarations rather than hand-written.
- [ ] #6 The reference application declares its flags with the new syntax, keeps its `ExampleInput`, and every existing parity test passes unchanged.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
- 2026-11-03: AC#1 landed; AC#2 and AC#3 were rewritten on the way, and this note says why rather than leaving the renumbering to be inferred. The old AC#2 required the macro to *generate* the input bridge, which it already does today through `#[facet(input = …)]` and `#[derive(Facet)]` — the derive copies fields by name whether the field used `#[arg(..)]` or `#[clifacet(..)]`, because the attribute is consumed into an `#[arg(..)]` before clap's derive and `Facet` see the field. Writing a second bridge generator would have been the duplicate this crate exists to avoid. The AC now says what is actually owed: the interaction and normalization keys have to be *consumed* by the generated collection and bridge instead of being forwarded; today they are rejected with 'not a key this attribute forwards'.
- Grammar keys are forwarded as tokens, never reinterpreted: `short = 'n'`, `value_parser = clap::value_parser!(u8).range(1..=8)` and `range = 1..=8` all reach clap exactly as written, which keeps decision-2 intact. The key table is split three ways — 17 value keys, 5 flag keys, and `long`/`short` accepted either bare or with a value, because clap accepts both and a single category would have made `#[clifacet(long)]` fail on the most common spelling.
- Two rules, both tested: an unknown key is a compile error whose message names the supported keys and points at the key rather than the whole attribute, and a key declared twice is an error rather than last-one-wins. Both have golden trybuild files, including the full key table — the guide and the goldens are edited together on purpose, so the surface cannot drift from its documentation.
- The escape hatch is tested as a composition, not just as passthrough: `tests/ui/field_attribute_valid.rs` declares one field with `#[clifacet(..)]` and another with a raw `#[arg(..)]`, and asserts clap's rendered help shows both.
- BDD: `examples/simple/tests/features/facet_bridge.feature` gained 'A field declared once carries its own grammar' with four steps, driven through public seams only — the help is clap's `render_help()`. The declared command lives in the example crate's tests rather than in `examples/simple/src` because AC#6 moves the reference application over once the interaction half exists; moving it now would have changed the example twice.
- Docs: `docs/derive.md` gained a 'Declaring one field once' section with the full three-way key table and the escape-hatch rule; its snippet is compiled by `check-docs` (13 snippets, 10 pages). `docs/development.md` states the new cfg-site guard and the single `json` exception.
- Evidence: `trybuild` 3 cases pass; workspace 302 Rust tests; 315 Python tests; `check-features` 5 configurations compile; clippy `-D warnings` clean; `cargo fmt --check` clean; `check-docs` clean.

- 2026-11-03: decision-13 accepted by the maintainer; AC#2, AC#3 and AC#4 landed. The decision's implementation note records every place the build differs from the proposal.
- **Shape.** `#[clifacet(..)]` stays a pure forwarder: grammar keys become `#[arg(..)]`, every other key becomes a field-level `#[facet(..)]`. The `Facet` derive is the only generator and reads those field keys (new `clifacet-macros/src/rules.rs`). Without a `bridge` it now generates `TryFrom<Cli> for Input` (`validate` delegates to it) and always generates `clifacet::prompt::Collect`. The library adds `prompt::Collect`, `Session::ask_for`, `Session::confirm_flag` and a `#[doc(hidden)] facet::__derive` module with the rules as traits (`Text` for `trim`/`non_empty`, `Credential` for `secret`). Each trait carries `#[diagnostic::on_unimplemented]`, so a rule on the wrong type names the rule and the type.
- **Asking without a second parser.** `ValueParser::parse_ref` and `AnyValue` are crate-private in clap 4.6. `ask_for` therefore parses the answer with the *real* command, cloned: environment fallbacks cleared, a sentinel subcommand with `subcommand_negates_reqs` so required siblings do not interfere, and `try_remove_one::<T>`. clap raises value-parser errors before validating relations, so a rejected answer is a validation failure in clap's words (`invalid value '9' for '--count <COUNT>': 9 is not in 1..=8`). A clone of only the `Arg` was rejected: `required_if_eq*`/`default_value_if` cannot be reset and would reference ids that do not exist, which clap's debug assertions turn into panics. This removes decision-13's "named parser path" rule; positional arguments still cannot be asked for (compile error).
- **TDD evidence.** `crates/clifacet/tests/declared_fields.rs` was written first and failed to compile for the intended reasons: "`ask` is not a `#[clifacet(..)]` key this attribute forwards" and "unresolved import `clifacet::prompt::Collect`". Of its first 15 tests, one failed after the implementation. That was a test mistake, fixed in the test: the interactive `--yes` case left `--count` unsupplied, and `--yes` answers confirmations, never missing values. The code was right. Seven edge-case tests followed: blank/empty answer, hyphen-leading answer, short-only option, required sibling argument, choice list. All passed first time and now total 22.
- **Bugs found in the merged AC#1, fixed test-first.** Adding `#[clifacet(long, required)]` to a test exposed that the key table did not match clap's derive. The valid trybuild fixture was extended with the clap spellings and failed (`required` takes no value), then passed after the fix. (1) `required` and `hide` were bare-only flags, but clap's derive accepts only `required = true`, so `required` was unusable either way. (2) `long_alias` is not a clap 4 method. Replaced by `visible_alias`, which the fixture's comment had claimed was forwarded and was not. (3) `range` is not a clap attribute: forwarded "exactly as written", it became `Arg::range`, which does not exist, so the claim in the note above was wrong. It is now translated to `value_parser = clap::value_parser!(T).range(R)`, with `Option`/`Vec` peeled. (4) `env`, `default_value_t`, `value_parser` and `action` were value-only, but clap accepts them bare. (5) `clifacet-macros` relied on clap_derive to enable `syn/full`, without which `range = 1..=8` and `value_parser = …range(..)` do not parse. Standalone `cargo test -p clifacet-macros` showed it. Now declared; `Cargo.lock` unchanged.
- **Compile errors (AC#4).** Six new trybuild cases, each pointing at the key: `field_confirm_not_bool`, `field_ask_not_option`, `field_ask_secret`, `field_ask_positional`, `field_rule_wrong_type`, `field_rule_beside_bridge`. Goldens generated with `TRYBUILD=overwrite`, never hand-written. The unknown-key golden was regenerated for the new table.
- **BDD.** `examples/simple/tests/features/facet_bridge.feature` gained two scenarios, both driven through clap, `Collect` and `Facet::validate` on a scripted session: 'A field declared once is asked for and normalised by the same declaration' and 'Without a terminal the declared default fills in and nothing is asked'. They were written after the implementation; the red evidence is `declared_fields.rs` above. The `declared` module's name field now carries `ask`/`fill`/`trim`/`non_empty`, and `DeclaredInput.name` is a `String`.
- **Docs.** The `docs/derive.md` 'Declaring one field once' section is rewritten with the corrected key table, the rule order, the compile errors and a compiled snippet that asks and normalises. 'Two ways to build the input' became three. The rustdoc on the derive and on `Facet` lists the field keys.
- **Evidence.** `lint` (clippy `-D warnings`) and `fmt-check` clean. `test-src` 46, `test-integration` 291, `test-doc` ok (including the new `prompt::Collect` doctest). `coverage` 96.31% (1540/1599, target 90%). `check-features` all combinations compile. `test-scripts` 315 passed, 2 skipped. `check-docs` 10 pages, 13 snippets. `alint` 46 rules, plus `skills-check`, `sandbox-check`, `check-packages`, `check-advisory`, `deny-offline` and `actionlint` all clean.

AC#6 changes the documented decline message, because a generated `confirm` names the question and the flag. The example's `--repeat` range and blank-credential rules can move onto fields then.
